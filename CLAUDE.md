`engine/tests/test_spice.py`'s end-to-end tests are gated on ngspice being on PATH (`brew install ngspice` / `apt-get install ngspice`), the same convention `test_live_model.py` uses for an API key — without it they skip and the suite still passes, so a green run does **not** by itself mean simulation was exercised. CI installs ngspice on Linux and macOS; the Windows job skips them.

The web toolchain needs **Node 22 or newer** (`node --version`); CI pins 22, and Vite 8 refuses to start on anything older.

Restart the Vite dev server after heavy on-disk churn (agent edits, branch merges). A long HMR history can make it serve one module under two `?t=` stamps in the same page, splitting singletons like the run store and the log ring buffer into duplicate instances — the SPA then behaves impossibly: empty feed and debug console, or the view stuck on the intent form while a paid run completes invisibly (diagnosed 2026-08-30; check `performance.getEntriesByType('resource')` for duplicate `/src/lib/run.js` URLs). The built bundle served by the service is immune.

Only the CLI reads `.env` (`cli.py:_load_dotenv`); `service/app.py` does not — export `GOOGLE_API_KEY` into the environment when launching the service (e.g. `set -a && . ./.env && set +a` in Git Bash).

Pytest config lives in `pyproject.toml` (`testpaths = engine/tests, service/tests`; `pythonpath = engine, .`). CI (`.github/workflows/ci.yml`) runs install + ruff + pytest + check_docs on Linux/macOS/Windows, Python 3.11, and has two further jobs the Python commands above do not cover: `web` (Node 22, in `frontend/`: `npm ci` + `npm test` + `npm run build`) and `docker` (a `docker build .`). Do not quote test counts in prose anywhere — the number has drifted repeatedly (40, 54, 143, 160) and `check_docs.py` only guards README and DEVPOST.

## Architecture

The installed `silkscreen` package lives under `engine/` (setuptools packages only `engine/`), with the Cloud Run surface in `service/`. The core pipeline is: parse a `.kicad_pcb` file, solve placement with CP-SAT, write the placements and board outline back into the file. A generated run additionally draws a `.kicad_sch` and lays copper, so it leaves a whole KiCad project rather than one placed board. The board file is the API — there is no KiCad process, plugin, or IPC anywhere. The design is layered: the deterministic engine makes no network calls; `agents/` is the only place a model call lives; `service/` is the only place GCP lives. Each layer keeps an offline stand-in (`ScriptedModel`, `MemoryFactStore`) so the whole suite runs with no keys.

Core engine modules, in dependency order:

- **`units.py`** — every dimension in the codebase is an **integer nanometre** (KiCad's internal unit). No floats flow through the pipeline; unit confusion (mm/mil/nm) is treated as a board-destroying bug class. Provides `mm()`/`mil()`/`to_mm()` and grid quantisation (`DEFAULT_GRID_NM` = 0.05 mm, `DEFAULT_CLEARANCE_NM` = 0.25 mm).
- **`packing.py`** — the OR-Tools CP-SAT placer. `pack(parts, nets=..., clearance_nm=..., time_limit_s=...)` minimises HPWL wirelength plus board area and returns a `PackResult` with status `OPTIMAL` / `FEASIBLE` / `FALLBACK` (a shelf-pack fallback fires when CP-SAT finds nothing in budget). `FEASIBLE` is the normal outcome on real boards. Determinism requires `workers=1` (the default) — multi-worker CP-SAT is non-deterministic regardless of seed. Power nets are down-weighted (not dropped) via the `is_power_net` heuristic in kicad.py. `edge_refs`/`rotatable_refs` naming a ref not on the board is a hard error, not a no-op.
- **`kicad.py`** — `.kicad_pcb` read/write via `kiutils` (pure Python). `load_board` then `extract_parts` yields `FootprintInfo` (courtyard extents from `F.CrtYd`, falling back to the pad bounding box; per-pad offsets; pad-to-net map). `extract_nets`/`extract_wires`/`to_parts` build solver input. After solving, `apply_placements` moves footprints and `set_board_outline` draws `Edge.Cuts` (without it the board has no boundary and edge constraints mean nothing), then `save_board`. **Coordinate frames:** the solver works Y-up; KiCad is Y-down. kicad.py owns the flip at both boundaries (pad offsets in, placements out) — never convert anywhere else. Output format is `20240108` (KiCad 7–8). Geometry extraction is shape- and rotation-aware (PR #6): `_courtyard_points` dispatches on graphic type — `fp_poly` vertices, exact circle bounds, arc bulge via `_circumcentre` — and `_rotate_mm` maps footprint-local geometry through the footprint's existing angle, exact at any rotation, not just 90° steps. `extract_parts` and `apply_placements` share one identity rule, `_placer_ref` (reference designator, falling back to library name), and `to_parts` raises `ValueError` on duplicate refs or on footprints with neither — identity problems raise instead of silently no-opping, the same convention as `edge_refs`. The bug class all of this guards against never raises on its own: the solver reserves a box that doesn't match the part actually written, the run reports success, and the opened board has parts stacked on each other. Regression tests for this class compute expected geometry from the raw file with independent math that never calls kicad.py (the overlap truth function in `engine/tests/test_kicad.py`) — a check written in terms of the code under test would share its blind spot.
- **`netlist.py`** — validated circuit IR, the contract between an LLM and anything touching KiCad. `parse_circuit_spec` accepts raw model output (fenced JSON tolerated), and **collects all validation failures into one `ValidationError`** so the whole batch can go back to the model as a single repair prompt. Connections require pin-level terminals (`C1.1`, not `C1`) because "one leg of this capacitor to this pin" must be expressible.
- **`schematic.py`** — emits a complete `.kicad_sch` plus the `.kicad_pro` that ties it to the board, from the same `CircuitSpec`. Symbols are **generated, not looked up**: the file carries its own `lib_symbols`, so it opens where no KiCad library is installed and cannot resolve to a different part than the one drawn. Connections are a short wire stub per pin to a **net label**, not point-to-point wires. **Coordinate frames:** symbol libraries are Y-up, the sheet is Y-down, and `_pin_on_sheet`/`_stub_on_sheet` are the only two places that cross — reaching for `SymbolPin.stub` directly and adding its symbol-local `dy` to a sheet coordinate is how every passive's net label ended up drawn on its own body. The schematic and the board must agree on what `C3` is, which is what `CircuitSpec.assign_refs` exists for: both emitters call it rather than numbering parts themselves.
- **`routing.py`** — a two-layer A* grid maze router over a 0.25 mm lattice with an explicit via cost, nets routed one at a time. **Not a competitive autorouter and it does not pretend to be:** a uniform grid cannot reach every pin of a fine-pitch package, and the contract is honesty — every net it cannot finish is named in `RouteResult.unrouted` with a reason and left as ratsnest. A refusal names the nets it covers too, or `completion` reads an empty result as 100%. **Clearance is enforced inside the search**, against a map of committed copper centrelines, not by the halo `_commit` writes: that halo cannot claim a node another net already owns (pad keep-outs own many), so relying on it produced real shorts. Vias are tracked separately from tracks because a barrel is wider and the neighbour's shape sets the spacing. Two search budgets bound the work, in **node expansions rather than seconds** — the same design must route the same way twice — sized from measurement (400k total, 150k per net).


- **`spice/`** — SPICE simulation as a **verifier the agent calls in a loop**, not a waveform viewer. DRC checks geometry; this is the only thing in the repo that checks *function*. `deck.py` turns a `CircuitSpec` plus a `Testbench` (sources, one analysis, models) into a netlist; `measure.py` extracts declarative quantities (rise time, ripple, gain, `abs_max` for absolute-maximum ratings); `assertions.py` turns a specification into pass/fail with the measured number and a **signed margin** on every clause; `simulators.py` puts ngspice and LTspice behind one interface; `raw.py` reads both rawfile dialects; `spec.py` is the JSON bridge the MCP `simulate_circuit` tool uses. Design rules, all load-bearing: **nothing returns a quiet zero** — every failure path raises a specific error from `errors.py`, because an agent that gets an empty result concludes the circuit is fine; a measurement with no answer (rise time of a flat signal, a probe on an absent node) raises rather than returning 0.0, and fails its clause rather than passing vacuously. Two boundaries are stated rather than hidden: **a `Device` is a pin map with no behaviour**, so simulating one needs a caller-supplied `SubcircuitModel` and otherwise raises `UnsimulatableError` naming the part (a crystal is the same case); and **a circuit is not a testbench** — the IR never says what drives it, so `Testbench` is separate and a source on a net the circuit lacks is an error, not a floating node. ngspice exits **zero** on a singular matrix and writes a well-formed rawfile, which is why `RunOutcome.warnings` exists and why `Testbench(strict=True)` (promoting warnings — a substituted generic diode, a floating pin — to errors) is the right default for an agent verifying a spec. Values follow SPICE's own syntax exactly (`M` is milli, `MEG` is mega) and reach the deck as scientific notation so the simulator cannot reinterpret a suffix; net names are sanitised to SPICE nodes and relabelled back on the way out, so a caller only ever sees its own vocabulary. Real data is never passed through `abs` — a node at -5 V must not measure as +5 V and pass an absolute-maximum check it violates. Regression tests check simulated numbers against closed-form theory computed inline (`tau*ln(9)`, `1/(2*pi*R*C)`), the same independent-math discipline `test_kicad.py` uses for overlap.

Layers above the core:

- **`agents/`** — the Gemini-backed layer. Worker stages stay behind the `Model` protocol: `GeminiModel` calls `google-genai` (`generate_content` with document parts); `ScriptedModel` keeps tests offline; `FallbackModel` (resilience.py) does provider failover. The web presentation path adds `adk/orchestrator.py`, a genuine ADK `LlmAgent` that may ask one essential clarification and otherwise calls the validated pipeline through one `generate_board` tool. The root uses ADK-native model access and emits correlated model/tool callbacks; its offline tests inject a fake `BaseLlm`. `pipeline.py` runs read, propose, validate, place, schematic, route, review; `propose.py` drives the batched repair loop against `parse_circuit_spec`; `review.py` is an adversarial critic whose findings are filtered against the actual spec; `retrieval.py` does embedding retrieval with asymmetric task types. `board.py`, `footprints.py`, and `cli.py` (`python -m silkscreen "..."`) turn a validated spec into a board. `generate_pcb` takes an optional `on_event` callback — an ADK-shaped seam that deliberately mirrors ADK's callback/event model (team decision 2026-08-30), and it is now driven from both sides: the straight-line SDK driver and the ADK `Workflow` in `agents/adk/` run the same six stage bodies in `agents/stages.py` and emit through the same seam. `schematic_stage` is the only stage body that touches the filesystem — it writes the `.kicad_sch`, `.kicad_pro` and pre-routing `.placed.kicad_pcb`, and does nothing at all without an `output` path, which is why the service (which passes none) never emits `schematic` events and the SPA has no rail row for that stage. `route_stage` mutates the board in place so the headline `.kicad_pcb`, written last, carries the copper. The normal stream omits board text, raw model output, and untruncated errors; debug chat streams additionally include worker and orchestrator requests/responses, each bounded and correlated by call id. Callback exceptions deliberately abort the run; the service relies on that to stop a run whose client disconnected. The layout follows that split: `stages.py` holds the shared stage bodies, `adk/workflow.py` builds the `@node` graph, `adk/runner.py` owns the workflow runner and token registry, and `adk/orchestrator.py` owns the conversational root. Driver precedence is `engine=` keyword, `SILKSCREEN_ENGINE`, then the `adk` default (`sdk` is the kill switch). `engine/tests/test_agents.py` pins the SDK driver and `engine/tests/test_adk.py` pins parity between the two.
- **the ordering lane** — `fab.py` renders the fab package (RS-274X Gerbers, two Excellon programs, BOM, pick-and-place, drill report, `README-fab.txt`), `order.py` holds the order options and the older narrow preflight, `fabhouse.py` knows the real fabs, `gate.py` is the pre-flight verification gate, `approval.py` assembles the prepared order, and `ordercli.py` is `silkscreen-order`. Four things are load-bearing. **Gerber is Y-up**, the same handedness as the solver, so `fab.py` performs no flip — it shifts every coordinate by the outline margin instead, putting the board's bottom-left corner on (0,0), because some fabs reject negative coordinates outright; under `%FSLAX46Y46*%` with `%MOMM*%` one Gerber coordinate unit is exactly one nanometre, so the engine's integers are written verbatim. **Excellon has no per-hole plating field**, so plating is carried by which file a hole is in: `silkscreen-PTH.DRL` and `silkscreen-NPTH.DRL` both always ship, and shipping only one is how a via gets drilled unplated — an open circuit between the layers that passes every visual inspection. **The gate's checks come from subsystems that share no code** (netlist, packing, `audit/rules.py`, `fabhouse.py`, `kiutils`, and readers in `gate.py` that re-parse the emitted files) for the same reason `audit/geometry.py` is a second reader rather than a caller of `kicad.py`; `gate.REQUIRED_FILES` is spelled out rather than derived from `fab_files()`, since asking the generator what it generated cannot catch the generator dropping a file. `CheckStatus.SKIPPED` **blocks exactly as FAIL does** and has no downgrade flag — an unrun check proves nothing, and every check carries its measurements on a pass as well as a failure. **Nothing in the package submits an order.** There is no submission path, no payment path and no stored credential; `PreparedOrder` exposes no `submit`/`confirm`/`place`/`approve` (asserted by a test over its public surface), `fabhouse.submit_order` exists solely to raise, and `fabhouse.SUBMISSION_BOUNDARY` carries the reasoning. Do not add one, do not add a `--yes`, and do not wire a fab's authenticated API: the project holds no fab credentials and creates no fab accounts, which is why OSH Park (a published price *rule*, computed exactly over the routed outline) is the only house that returns a number, while JLCPCB and PCBWay return `PriceBasis.UNAVAILABLE` with `None` — never zero — in every money field.
- **`mcp/`** (inside `engine/silkscreen/`) — a real MCP server: JSON-RPC 2.0 over stdio, exposing engine operations as tools. `handle()` maps one request dict to one response dict and never touches a stream, so the protocol is testable without spawning a process. Console script: `silkscreen-mcp`.
- **`audit/`** (inside `engine/silkscreen/`) — the optional visual design review, behind its own console script `silkscreen-review` (never run by `generate_pcb`). It reviews a finished `.kicad_pcb`, whoever produced it. Two halves that are deliberately never merged: `rules.py` measures the board and may only report what it measured (each finding carries its measurement in `evidence`), and `judgment.py` asks a model for the findings no rule can express. The first produces `Origin.PROVEN`, the second `Origin.SUGGESTED` — a constructor in `_parse_findings` fixes that, so nothing a model returns can enter as proven, and a model failure loses only the suggested half. A suggested finding naming no part the board contains is dropped rather than reported unlocatable. `geometry.py` is a **second, independent reader** of `.kicad_pcb` (absolute coordinates, KiCad Y-down frame) rather than a caller of `kicad.py`: a checker written in terms of the code that produced the board shares its blind spots, the same reason the placement tests compute expected geometry independently. `effort.py` is the thinking slider — `quick`/`standard`/`deep`, where each level runs a strict superset of the level below (asserted by test) and deep adds a refutation round every model finding must survive. `render.py` draws the board with findings marked at their locations, severity by colour and origin by line style; it performs **no Y flip**, because SVG shares KiCad's handedness and the project's one flip belongs to the placer boundary. `report.py` emits a self-contained HTML page, a terminal report and JSON, each stating which rules ran and which model passes happened, so an empty finding list cannot read as a clean board.
- **`service/`** — the Cloud Run surface: `app.py` is a stdlib-only HTTP server over `silkscreen.agents.generate_pcb`; `cache.py` is a Firestore-backed datasheet-fact cache, `models.py` discovers the current key's `generateContent` Gemini models with a fifteen-minute cache and explicit fallback catalog, and `quota.py` provides a process-wide minimum-interval gate for explicit generative calls. Deployment uses the root `Dockerfile` (a node stage builds `frontend/dist` into the image). `POST /generate` remains the compatibility route and `POST /generate/stream` its live NDJSON variant. `POST /chat/stream` runs the ADK root, validates an independent orchestrator model plus `auto`/`low`/`medium`/`high` thinking level and Auto/15/6/3 RPM request pace, emits versioned session/turn/event envelopes, and lets its `generate_board` tool invoke that same generator; presentation settings are stripped before tool execution, while pacing is applied at each ADK round trip and every worker fallback attempt. `quota.wait` makes intentional delays visible. This gate coordinates threads in one service instance; it cannot coordinate Cloud Run replicas or alter Google project/model TPM and RPD quotas. `GET /models` backs the key-aware selectors. The additive response includes `routing` so the root can name unrouted nets honestly. `placements` carries solver-Y-up geometry, leaving exactly one Y flip to the client. The built bundle is served same-origin (`SILKSCREEN_WEB_DIST` overrides), with `/healthz` taking precedence and deliberately no CORS/OPTIONS support; keep explicit content types because Windows maps `.js` incorrectly. Debug chat streams expose bounded raw model requests/responses for both layers, while one-shot responses do not. All stream routes share the existing error taxonomy; pre-stream validation failures remain plain JSON 400/413.
- **`frontend/`** — a Svelte 5 + Vite plain-JS SPA preserving the Drafting Table/Night token system. **Chat** is the default centre tab: `ConversationView` keeps the user request, one optional clarification, friendly activity summaries, assistant output, failure recovery, and compact artifact cards in one transcript; `ActivityCard` expands bounded raw prompts, responses, and tool payloads. `session.js` saves/opens a size-limited, schema-versioned JSON snapshot of the transcript, trace, result, and board artifact. The initial intent form selects Gemini 3.7 Flash or the available Gemini 3.1 Pro Preview for the root, Auto/Fast/Standard/Deep thinking effort, and an Auto/15/6/3 RPM request pace; Gemini 3 cannot turn thinking fully off, so Fast maps honestly to `low`. The pace survives clarification, retry, and session JSON, and visible `quota.wait` activity distinguishes deliberate spacing from a hung call. `GET /models` disables models the current key does not advertise and supplies the broader retry list. The existing Schematic, Board, and Review tabs remain hash-addressed and cross-highlight findings; solver-Y-up becomes SVG-Y-down exactly once in `board.js`. `src/lib/api.js` remains the only `fetch`; chat streaming never replays a malformed or interrupted paid run. Every server event is also mirrored through the existing scrubbed, bounded debug log, and the in-app console remains the only full debugging surface. Session exports contain raw debug prompts/responses by request and should therefore be treated as sensitive design artifacts. Voice remains the only unbuilt feature-9 item. Orthogonal to theme, the persisted `paper`/`glass` skin changes material without entering API requests or saved sessions. Every high-level material surface declares a `data-material` role: `chrome`, `panel`, `popover`, and `sticky` receive the skin's backdrop filter; `tint` and `canvas` are explicit no-filter roles that prevent nested blur and preserve the board and schematic drawings. `glass.css` supplies both light and dark translucent palettes plus an opaque reduced-transparency fallback, while `--board-*` remains unchanged.

`data-testid` convention: ids sit only on intrinsic elements, never on component tags, since every component destructures `$props()` without spreading rest props onto a host element; a repeated row (a finding, a board part) shares one id across instances, disambiguated by identity attributes such as `data-ref` or `data-sev` rather than an index suffix, which would make the id encode array position instead of role. Nothing strips these in production — the bundle is same-origin and under 5 KB of attributes, and e2e/agent QA should exercise the shipped build, not a stripped one.

Tests live in `engine/tests/` and `service/tests/`; the shared fixture is `engine/tests/fixtures/ref.kicad_pcb` (an 11-footprint STM32 board). The round-trip property — written board reparses, keeps every footprint, no overlapping courtyards — is enforced by test. The fixture's nets are named `0_device_pin_N`, so the power-net heuristic does not fire on it; that path is covered by unit tests only.

## Hackathon requirements

The submission must satisfy three Google-stack constraints; design any new AI or agent work against them:

- Models: Gemini 3.5 or newer, called through the Gemini API or Vertex AI.
- Frameworks: at least one Google agent framework — Google ADK, GenAI SDK, Antigravity SDK, or Genkit.
- Infrastructure: at least one Google Cloud infrastructure service.

All three are currently met — Gemini 3.7/3.5 models via the Gemini Developer API, Google ADK (dynamic workflows) as the framework with the GenAI SDK underneath it for model access, Cloud Run plus Firestore as the infrastructure. Per-requirement analysis with citations lives in `docs/gemini.md`, `docs/agent-framework.md`, and `docs/cloud-infrastructure.md`. The engine itself stays key-free and offline-testable; `GOOGLE_API_KEY` in `.env.example` serves the agents layer only.

ADK decision (reversed 2026-08-30): the pipeline is a Google ADK 2.8 dynamic `Workflow` selected through `generate_pcb` and `SILKSCREEN_ENGINE`. The presentation layer now also has a genuine ADK `LlmAgent` root in `agents/adk/orchestrator.py`; it owns the clarification/tool decision and calls the existing workflow through `generate_board`. Worker model access remains behind the `Model` protocol until the scripted-LLM and failover guarantees can migrate safely. `adk api_server` stays off the request path: its separate port, event-array response, and lack of static serving conflict with this repo's same-origin service contract. The settled design is therefore ADK-native root, ADK workflow, tested worker protocol, and one stdlib service surface.

## Documentation discipline

The README's measured figures (board size, HPWL) are reproduced exactly by `scripts/demo.py`; if a change shifts them, rerun the demo and update the README rather than leaving stale numbers. Test counts in README/DEVPOST are enforced by `scripts/check_docs.py` in CI, and `check_docs.py --fix` rewrites the stale numbers in place. Unbuilt features are tagged `[not yet built]` in DEVPOST.md — keep unbuilt work visibly unbuilt. `check_docs.py` checks every "N tests" claim in README/DEVPOST against pytest's own collection count: a line naming one of its `MODULES` keys (`packing.py`, `agents/`, `service/`, …) is checked against that module's test files, and every other line is checked against the suite total. There is no `MODULES` entry for `frontend/`, so a frontend/Vitest count quoted in either file would fall through to the suite-total comparison and fail CI — never quote one there.
